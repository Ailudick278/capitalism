# 税务系统开发进度

## 已实现功能

- 支持企业所得税、个人经营所得税、土地税、增值税和资本利得税框架。
- 支持税单、申报、缴税、欠税、退税、抵扣、更正和审计记录。
- 企业从公司金库缴税时使用“税单 ID—扣款前已缴金额—本次金额”的稳定来源键；税单更新和付款流水恢复时不会重复扣款或重复增加已缴税额。
- 退税在消耗税收抵扣后才进入发放阶段；邮箱入账失败会保留请求供恢复器重试，发放阶段使用统一金融日志和稳定来源键，避免“抵扣已扣但退款未到账”。

## 存在的问题

- 居民 NPC 工资仍以家庭模拟收入为主，玩家工资和家庭消费税尚未统一纳入完整税基。
- 税率、免税额、地区税基和申报周期仍较简化，税务政策尚未形成完整的逆周期规则。
- 逐笔税单支付和按主体支付现在写入税单级稳定钱包扣款引用，扣款后税单更新前发生中断时可安全重试；税收抵扣与邮箱发放之间仍是两个持久化边界，统一日志目前主要承担阶段审计和重试定位。
- 政府福利和区域支持已具备家庭收款金额凭证，但 NPC 工资、消费仍未纳入统一税基；下一步将先建立居民税基和消费税凭证，再接入税率与免税额。
- NPC 家庭消费已开始接入 VAT：消费记录保存含税总价和税额，企业按净价入账，政府保存家庭—卖方—税额收款凭证，审计会核对三者关系。
- 工资支付已按配置所得税率拆分为毛工资、代扣税和家庭净工资；欠薪仍按毛工资累计，政府保存雇佣关系对应的代扣凭证，企业扣款与家庭净收入可分别审计。
- 工资税从 USD 结算单位转换为政府默认货币后再进入财政余额，工资凭证保留原始 USD 金额，审计同时核对两种货币口径。

## 后续方向

1. 统一玩家、NPC、企业工资及消费的税基和申报口径。
2. 按税种、地区建立预算分配和公共服务反馈。
3. 增加税务风险、稽查、罚款、退补税和政策调整机制。
