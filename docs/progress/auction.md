# 拍卖系统开发进度

## 已实现功能

- 竞价会在扣款前校验当前托管竞买人的身份和金额；异常竞价不会先扣款再进入无凭证退款分支，重试不会重复发放退款。

- 拍卖发布先保存持久化意图并托管商品，再写入拍卖记录；登录恢复可补建商品已托管但拍卖记录尚未落盘的列表，并使用仓储快照避免重复扣货。
- 拍卖挂单恢复不再依赖玩家重新登录：服务器运行期间会周期性重试，跨日结算的市场收口阶段也会再次恢复并处理到期拍卖。

- 支持物品挂牌、竞价、撤回和到期结算。
- 竞价资金进入托管，卖方离线时通过邮箱收款。
- 被抬价竞价者的退款使用“拍卖 ID—原竞价者—原竞价金额”的持久化凭证，在线与离线到账都可安全重试。
- 结算记录具备幂等标记，避免重复发放。
- 钱包引用支付现在具备金额与币种校验的幂等重试基础，可供竞价等前置扣款流程接入。
- 到期结算将货物交割/退回、卖家收款和销售税分别写入统一金融阶段日志，便于中断审计和后续恢复。
- `/economy-audit` 会列出仍未完成的拍卖挂单意图，恢复路径和审计输出使用同一持久化记录。

## 存在的问题

- 缺少统一合同、争议和拍卖失败的违约处理。
- 价格发现仍局限于单次拍卖，缺少历史统计。
- 竞价仍是“付款后写竞价记录”，但已使用稳定的拍卖—竞买人—金额支付引用；扣款后服务器中断时，重试会识别原付款并补写竞价记录。统一待处理事务日志仍待建设。

## 后续方向

- 拍卖审计已覆盖活动拍卖、出价历史、结算标记和挂单恢复意图；后续继续把托管商品数量与统一交割流水逐笔关联。
- 拍卖结算日志现在必须能落到活动拍卖或已结算标记；终态按退货路径或成交交付、收款、税务三阶段验收。

1. 接入统一合同状态和交易凭证。
2. 增加拍卖历史、估值和市场信息展示。
3. 增加保证金、恶意竞价和争议处理。
