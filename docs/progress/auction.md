# 拍卖系统开发进度

最后更新：2026-09-05

## 已实现功能

- 拍卖作为独立系统维护拍卖对象、拍卖市场和持久化数据。
- 支持挂牌、竞价、最高价维护、成交和相关网络消息基础结构。
- 土地系统已经具备土地拍卖数据入口，可为区块转让提供基础。
- 拍卖相关方可通过命令和界面参与操作。
- 普通物品拍卖的结束时间改用持久化 `gameTime`，服务器重启后不会重置或延长拍卖周期。
- 增加了竞价金额溢出校验，以及异常商品/竞买人记录的保留和管理员修复提示，避免结算时吞掉托管资产。

## 当前边界与待处理问题

- 拍卖时间、保证金、自动延时、流拍、撤拍和违约规则仍需统一。
- 土地拍卖与普通物品/资产拍卖的差异化规则还可以进一步明确。
- 成交后的付款、过户、税费和失败回滚需要更强的事务保障。

## 后续开发方向

1. 完善拍卖生命周期和状态机。
2. 增加保证金、自动扣款、流拍、撤拍、违约和黑名单规则。
3. 将土地拍卖与土地所有权转移、土地转让税正式打通。
4. 抽象可拍卖资产接口，为未来扩展企业、库存和证券拍卖做准备。

# 拍卖托管结算幂等性（2026-09-06）

## 本次完成

- 新增拍卖结算账本，按拍卖单号记录已完成的托管释放或成交结算。
- 流拍时返还卖家物品后记录结算，再删除拍卖单。
- 成交时向赢家交付物品、向卖家付款并完成税务登记后记录结算，再删除拍卖单。
- 无出价撤单也使用同一账本，避免托管物品因异常中断丢失或重复返还。
- 新增竞价操作账本；竞买人付款和前一最高价退款完成后，即使最高价写回被中断，也不会重复扣款或重复退款。

## 现实逻辑对应

拍卖中的商品和竞价款在成交或撤单前属于托管资产；拍卖结束后应完成一次结算并关闭订单。本次增加了结算凭证，使拍卖记录与托管资产释放保持一致。

### auction-id-integrity-2026-09-06.md

# 拍卖 ID 完整性 — 2026-09-06

## 本次修复

- 活动拍卖注册表现在拒绝空 ID 和重复 ID。
- 加载旧存档时自动过滤空 ID 与重复拍卖记录。
- 拍卖结算日志以唯一拍卖 ID 为边界，避免同一拍卖被重复结算或重复交付。

## 数据安全原则

拍卖的物品托管、竞价托管和最终结算必须绑定同一个不可重复的拍卖标识。唯一性校验放在持久化台账层，而不是只依赖命令入口生成随机 UUID。

## 后续方向

- 为拍卖增加卖家托管、当前最高出价和结算状态的独立状态机。
- 将竞价退款、成交收款和物品交付拆成可查询的结算流水。

### auction-withdrawal-2026-09-06.md

# 无出价拍卖撤回（2026-09-06）

## 本次实现

- 卖家可以使用 `/marketorders cancel <拍卖ID>` 撤回尚未收到任何出价的普通物品拍卖。
- 撤回后立即返还托管在仓库中的商品。
- 一旦出现最高出价，卖家不能单方面撤回，避免破坏竞买人的资金托管和竞价预期。

## 现实逻辑对应

拍卖开始前或无有效竞价时，委托人通常可以撤回标的；形成有效竞价后，撤回应受到更严格限制，避免损害竞买人权益。

## 后续方向

- 增加拍卖撤回手续费、争议期和管理员仲裁记录。
- 将普通物品拍卖与土地拍卖统一到同一套状态机和托管凭证接口。
