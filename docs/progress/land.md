# 土地系统开发进度

最后更新：2026-09-05

## 已实现功能

- 以区块为单位进行土地持有和管理。
- 支持区块选择、认领、释放、租赁和转让。
- 支持土地用途、关联企业、资源数量和土地估值等属性。
- 支持所有者、租户、受信任玩家和访客等角色。
- 支持土地权限、信托管理、土地交易和拍卖数据持久化。
- 支持租金、租金欠款、宽限期、土地税到期时间和税务宽限期。
- 支持土地操作日志、土地状态、已持有土地和土地交易数据同步。
- 土地界面以世界地图作为区块选择入口，地图与土地业务逻辑已经分离。
- 租约结束后的未缴租金现在进入独立持久化债务账本；租客上线时自动尝试补缴，房东离线时通过邮箱收款。
- `/land lease` 与 `/land unlease` 现在统一走土地服务层，命令入口不再绕过土地冻结、租约和欠款状态校验。

## 当前边界与待处理问题

- 土地规则已经具备核心骨架，但还需要进一步统一所有权、租赁、转让、拍卖和税务之间的状态流转；租赁欠款已不再随租约结束丢失。
- 土地界面仍属于基础功能界面，后续可以在不改变领域逻辑的前提下重做 UI。
- 土地与企业、用途、基础设施的联动规则还需要继续细化。

## 后续开发方向

1. 完善土地状态机：可用、已持有、出租、出售中、拍卖中、欠税处置等状态互斥且可追踪。
2. 统一土地交易流程：报价、合同、付款、过户、失败回滚和日志记录。
3. 完善租赁合同：押金、周期租金、续租、违约、收回和争议处理。
4. 将土地价值、用途、位置、基础设施和周边市场纳入更稳定的估值模型。
5. 增加土地业务与企业、税务、物流的事件接口。

# 土地拍卖托管退款（2026-09-06）

## 本次实现

- 土地所有者在拍卖结束前补缴欠税赎回土地时，自动退还当前最高竞买人的出价。
- 在线竞买人直接收款，离线竞买人进入邮箱，和拍卖流拍、管理员取消、无效记录审计使用相同的退款方式。
- 只有赎回缴税成功后才执行退款和移除拍卖记录，避免缴税失败时拍卖状态被破坏。

## 现实逻辑对应

竞买保证金/托管款属于竞买人的暂存资金，不是土地所有人的收入；拍卖在交割前被撤回时，应解除托管并返还竞买人。

## 后续方向

- 为土地拍卖增加统一的状态机、争议期和成交交割凭证。
- 将土地转让税、欠税清偿和成交款分配统一纳入拍卖结算凭证。

### land-auction-settlement-idempotency-2026-09-06.md

# 土地拍卖结算幂等性 - 2026-09-06

## 本次变更

- 新增 `LandAuctionSettlementSavedData`，为土地拍卖的退款、产权转移、卖方分成、市场成交记录和最终关闭保存持久化结算键。
- 竞价被淘汰、土地赎回、管理员取消、孤立拍卖审计和缺失土地记录的到期清理统一使用退款账本，避免重启后重复退款。
- 到期成交会分别记录税款结算、产权转移、卖方分成、市场记录和通知步骤；已完成步骤不会在下一次 tick 重复执行。
- 土地税结算使用拍卖创建时的原所有者作为税务主体，避免土地转移后旧税被错误归属于新所有者。

## 现实逻辑对应

- 土地拍卖中的竞价款属于托管资金，未中标、撤拍或流拍时应退回竞买人。
- 欠税处置成交时，成交款先用于清偿原所有者对应的土地税，再将净额支付给原所有者，土地产权随后转移给最高竞买人。
- 产权、税务、资金和市场历史仍分别保存在不同的持久化账本中；本次增加的是跨账本恢复所需的步骤日志。

## 已知边界

- Minecraft `SavedData` 之间没有跨文件的原子事务。如果服务器正好在“资金转移完成、结算键写入前”崩溃，仍存在极窄的重复或遗漏窗口；当前账本可以恢复大多数“状态已保存但结算未完成”的情况。
- 后续可把土地拍卖的资金托管抽象成统一 escrow 账户，再将所有状态转换收敛到单一结算服务。

### land-auction-tax-settlement-2026-09-05.md

# Land auction tax settlement progress log — 2026-09-05

## Implemented

- Added a central `TaxService.settleFromProceeds` path for taxes withheld from an external settlement, without charging a player twice.
- Land auction proceeds now settle the seller's land-tax bills in the unified tax ledger and record tax payments.
- Auction settlement uses minor-unit ledger amounts before converting the withheld amount back to whole auction currency units.
- Land tax enforcement now verifies that the bill taxpayer still owns the claim, preventing an old owner's residual liability from freezing the buyer's newly acquired land.
- External settlement source IDs are persisted in the tax ledger, preventing the same auction proceeds from being applied twice after a reload or repeated settlement attempt.

## Design boundary

- Auction pricing, bid rules, disposal timing, and transfer-tax assessment were not changed.
- If auction proceeds are insufficient, the remaining seller liability stays in the tax ledger; it is not silently transferred to the buyer.

## Follow-up

- Add integration tests for full and partial auction-tax settlement.
- Add a dedicated seller-liability/auction history view when the land UI is revisited.

### land-lease-deposit-2026-09-06.md

# 土地租赁保证金（2026-09-06）

## 本阶段实现

- 新增 `landLeaseDepositRate` 配置，默认值为 `1.0`，表示保证金等于一个租金周期的租金。
- 签订租约时，从租客账户一次性收取保证金；租客必须在线完成签约。
- 保证金保存于独立的世界持久化台账，不混入 `LandClaim`，避免改变土地核心数据结构。
- 租约结束时，保证金优先抵扣已产生的欠租；抵扣后余额退回租客。
- 房东或租客离线时，款项进入现有邮箱，玩家下次登录领取。
- `/land info` 会向房东、租客和管理员显示保证金金额及租客标识，便于核对合同状态。

## 现实逻辑对照

保证金是履约担保，不是租金收入：租约正常结束应返还，只有可核算的欠租或损害才应扣除。本阶段先实现欠租抵扣，暂不把方块破坏、损害评估和争议裁决自动计入扣款。

## 后续方向

- 增加提前解约规则与违约金上限。
- 建立可审计的损害清单和双方确认流程，再允许从保证金扣除维修费用。
- 增加保证金状态展示、退款通知和管理员仲裁记录。

### land-lease-deposit-capacity-safety-2026-09-06.md

# 土地租赁保证金容量安全修复 — 2026-09-06

## 本次修复

- 修复保证金台账达到容量上限时更新已有土地记录会丢失旧保证金的问题。
- 已有土地的保证金现在原位替换或删除，不受新增记录容量限制影响。
- 只有全新土地记录且台账已满时才拒绝写入。

## 数据安全原则

容量上限只能限制新增数据，不能破坏已经存在的合同担保。该行为与保证金作为持续履约担保的性质一致，也避免服务器达到上限后造成不可追溯的资金损失。

## 后续方向

- 为保证金记录增加合同版本、收取时间、返还/抵扣状态和流水号。
- 增加容量接近上限时的管理员告警。

# 土地市场成交事件幂等性（2026-09-06）

## 本阶段实现

- `LandMarketSavedData.Transaction` 新增可选 `eventId`，旧版六参数构造方式仍然兼容。
- 新建的主动转让和土地拍卖成交记录使用结算流程生成的唯一事件号。
- 同一个事件号重复写入时只保留一条市场成交记录，避免服务器在结算步骤中断后重放造成重复统计。

## 现实逻辑对应

土地交易登记和市场统计应以一笔可追溯的成交事件为单位，而不是以每次执行代码为单位；重试不应创造第二笔交易。

## 后续方向

- 继续把土地交易、产权历史和税务票据统一到同一交易事件号。
- 增加管理员可查询的交易状态与异常结算修复入口。

### land-transfer-settlement-idempotency-2026-09-06.md

# 主动土地转让结算幂等性 - 2026-09-06

## 本次变更

- 新增 `LandTransferSettlementSavedData`，为协商土地转让保存买方付款、产权变更、市场成交和卖方收款等步骤。
- 买方确认转让时，系统会先建立唯一转让结算键；服务器重启后会跳过已经完成的步骤，继续未完成的过户流程。
- 转让请求只在卖方收款、税务交易记录和最终完成标记写入后删除，避免“请求已删除但卖方尚未收到款项”。
- 已经完成产权转移但请求尚未清理的旧状态，会被识别为已过户并继续完成剩余结算，不会重复扣除买方资金。

## 现实逻辑对应

- 土地转让被拆成合同确认、付款、登记过户、税费记录和卖方收款几个步骤，接近现实中的交易交割流程。
- 市场历史与税务记录分别保留，产权记录则由土地所有权历史单独维护。

## 已知边界

- 多个 `SavedData` 之间仍没有真正的跨文件原子事务；如果服务器恰好在资金操作完成、步骤日志落盘前崩溃，仍存在极窄的窗口。
- 后续可以把土地拍卖和主动转让都迁移到统一的土地交易托管服务中，减少重复的交割代码。
