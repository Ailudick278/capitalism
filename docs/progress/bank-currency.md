# 银行与货币系统开发进度

## 已实现功能

- 银行现金存入使用包含玩家、账户、币种、存入前余额和金额的稳定流水引用；账户状态已落盘后重复请求会直接识别为同一笔存入，避免网络重试造成重复扣现。
- 银行现金存入现在先保存持久化存入意图，并记录存入前现金面值；登录时可恢复物品已扣除但账户流水尚未写入的明确场景，无法确认时保留意图等待人工或后续协调器处理。

- 支持多货币、钱包、现金支付、兑换、汇率查询和转账。
- 支持银行账户、存款、定期存款、贷款、利息和交易记录。
- 银行取款和信用贷款在账户变更后使用稳定资金到账凭证，并通过邮箱统一发放实体货币，重复执行不会重复到账。
- 玩家登录时会扫描新格式的银行取款/贷款交易记录，自动补发账户已更新但服务器中断前尚未完成的邮箱到账。
- 危机期贷款容量以存款基础为上限，并随全系统逾期率提高而折减；逾期率达到 100% 时容量降至基础容量的 50%。
- 金融危机状态同时监测银行贷款/存款超过 120% 的资产负债压力，以及单日提款超过存款 50% 的挤兑压力；恢复必须满足逾期率和银行压力均回落。
- 危机解除采用连续三日恢复观测期，并持久化观测进度，避免指标在阈值附近波动造成危机状态反复切换。
- 危机期新增贷款额度在逾期率折减后再预留 8% 最低资本缓冲，避免银行在流动性紧张时继续把全部可用资金扩张为信贷；银行资本现已作为独立的持久化权益账本入账，并参与资本充足率判断。
- 银行现在拥有持久化权益账本：首次创建时注入可配置开业资本，日结按已记录的贷款利息收入减去存款利息支出更新资本，并以 8% 资本充足要求触发危机期停贷；日结日标记保证重复运行不会重复计入利润。
- 银行权益账本已纳入转账手续费收入和逾期贷款损失准备：逾期敞口按 50% 形成准备金目标，敞口下降时释放多余准备金，准备金变动通过当日损益进入资本。
- 资本收益汇总对异常的 64 位有符号数使用饱和绝对值，损坏或极端流水不会把收入统计反转为负数。
- 每日结算先生成当日银行流动性快照，再评估金融危机，存贷比和提款压力会在同一结算日生效，不再滞后一日。
- 全局日结新增持久化阶段日志，记录家庭/劳动力、信贷/证券和市场收盘三个阶段的开始与完成状态；中断后仍依靠各领域幂等凭证重试，日志用于恢复审计。
- 流动性快照会读取刚结束交易日的实际提款量，挤兑检测不再因跨日计数切换而恒为零。
- 转账使用持久化请求编号和回执，日结具备重复执行保护。
- 带请求编号的转账会把请求键写入付款方和收款方流水；重试时可识别只完成一侧的中断状态，补齐缺失的一侧后再写回回执，避免重复扣款。
- 管理员可使用 `/economy-audit` 检查企业账本余额链、家庭现金、工资债务和劳动记录。
- `/economy-audit` 现在也会列出银行现金存入、个人还款、货币兑换和玩家转账等仍未完成的金融意图。
- 银行权益结算逐笔记录利息和转账手续费收据；收据键不依赖最近 50 条流水的索引，离线玩家登录后补记的历史交易会进入同一权益账本，避免流水滚动后重复计入利润。
- 离线玩家登录时，存款正利息支出与贷款/手续费收入都会按同一交易来源幂等回灌银行权益账本，避免只统计一侧造成资本虚高。
- 工资结算现已使用公司来源标记、玩家邮箱凭证和 NPC 家庭来源标记，支持中断后的安全重试。
- 家庭现金流已产生可持久化的金融风险观察值，综合流动性短缺、住房欠款、工资欠款和失业期，为后续居民信贷定价提供输入。
- 玩家居民贷款额度已接入最近家庭风险评分：风险越高可用授信越低，风险满分不再新增授信；银行逾期和流动性约束仍独立生效。
- 家庭风险已接入贷款日息：基础利率仍由货币政策决定，风险评分最高增加 8 个百分点年化风险溢价，逾期贷款继续使用独立的逾期利率倍数。
- 银行风险敞口现在按玩家账户持久化快照保存，登录、登出和账户变更都会同步；流动性与金融风险统计包含离线玩家的存款、债务和逾期敞口。
- 债券提前兑付和到期兑付现在先记录政府扣款，再写入持久化市场邮箱凭证；服务器中断后可继续完成到账，避免政府已支出但持有人未收款，也避免重复兑付。
- 个人贷款还款先更新债务并写入带币种的付款凭证，再通过邮箱幂等支付出借人；每日结算会恢复尚未完成的出借人到账，旧付款记录保持兼容。
- 邮箱兑换只会删除已成功识别并发放的币种；旧存档中的未知币种余额会保留，不再因兼容性问题被静默丢失。
- 企业贷款还款使用“贷款 ID—原始余额—应计利息—还款额”的稳定扣款来源键；服务器在扣款后中断时重试不会再次扣款，仍会继续更新贷款余额和付款记录。
- 货币兑换使用持久化兑换意图、稳定扣款引用和独立的非收入转账邮箱；服务器中断或玩家离线后可恢复一次性到账，兑换结果不会伪装成新增收入。
- 玩家 `/pay` 使用带发送方、收款方、币种、金额和游戏 tick 的稳定转账来源；扣款后即使服务器中断，收款方登录或命令重试也不会重复到账。
- 玩家 `/pay` 现在先持久化转账意图，再执行稳定扣款和到账；恢复不依赖同一游戏 tick，跨 tick 重试也不会重复扣款。
- 银行个人还款使用持久化还款意图和稳定扣款引用；钱包已扣而债务尚未更新时，玩家登录会继续完成债务核销，重复请求不会重复扣款。
- 经济审计会检查银行资本、累计损益和损失准备金账本的溢出与边界状态。
- 货币兑换和玩家转账的服务器安全恢复现在每秒执行一次；已扣款但收款人离线时会直接写入持久化邮箱，不再依赖收款人重新登录或下一次日结。

## 存在的问题

- 现金物品消耗与账户状态写入仍是两个 Minecraft 操作；存入意图已能恢复明确的“现金已扣、账户未入账”场景，无法确认的异常仍会保留意图等待协调。

- 银行资产负债表和流动性压力测试仍不完整，资本账本目前覆盖利息、转账手续费、逾期准备金和达到配置逾期期限后的坏账损失；政府财政出资到银行权益也已提供可重试收据流程（`/government bank recapitalize`），尚未覆盖央行流动性工具。
- 不同系统之间的跨账本事务仍依赖各领域的阶段标记。
- 钱包附件、银行账户和邮箱仍是不同持久化边界，极端中断时还需要统一金融托管日志。
- 审计目前是只读诊断，不能自动恢复中断的跨账本事务。
- 账本单位边界已明确：企业金库和企业账本使用主货币单位；玩家钱包、邮箱、工资应付和居民家庭现金使用最小货币单位。劳动市场工资按 USD 最小单位结算，写入 NPC 家庭前按汇率转换为默认货币。
- 汇率和货币供给尚未受到人口、贸易和政策共同影响。

## 后续方向

1. 建立统一经济事件和结算凭证，并逐步替换各系统的专用意图表。
2. 将物流和税务结算扩展为统一的可恢复事务。
3. 完善银行资本、流动性、信用和挤兑模型。
