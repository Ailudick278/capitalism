# 人口与家庭系统开发进度

最后更新：2026-09-07

## 已实现功能

- 家庭以稳定 ID 持久化，记录区域、人口规模、劳动年龄人口、现金、基本生活需求和福利。
- 玩家登录后自动登记为家庭主体。
- 管理员可以按区域生成受控规模的虚拟 NPC 家庭。
- NPC 可以读取劳动市场岗位、自动匹配并形成雇佣关系。
- 工资日结进入 NPC 家庭预算，基本需求消耗预算，资金不足降低福利。
- 食品、能源和生活用品需求会按家庭规模、福利和商品价格折算，并参与现货市场价格更新。
- 岗位支持区域标识；低福利居民会在工资足以覆盖家庭基本需求时迁移到外地岗位。
- 家庭持久化健康和教育水平；每日结算会根据诊所、学校覆盖率更新两项指标，并同步劳动档案。
- 健康水平决定劳动参与率，教育水平逐步提高基础技能上限，形成公共服务到就业能力的反馈。
- 迁移判断会参考目的地物流基础设施的连通性；设施越少，迁移摩擦成本越高，避免仅凭名义工资产生不现实的跨区迁移。
- NPC 家庭现在按健康、福利和家庭规模进行确定性出生/死亡抽样；日种子由家庭 ID 和模拟日构成，重启不会改变结果。
- 家庭增加持久化平均年龄；每个模拟年推进年龄，出生会降低家庭平均年龄，年龄结构会影响出生率和死亡率。
- 家庭现在持久化儿童、劳动年龄和老年队列；出生进入儿童队列，年度老化推动队列迁移，死亡按老年、儿童、劳动年龄顺序处理。
- 管理员可用 `/population merge <source> <target>` 合并同区域 NPC 家庭；合并按人口加权整合现金、需求、福利、健康、教育、年龄和人口队列，玩家家庭不会被合并。
- NPC 跨区域就业会先检查并支付搬迁成本（两周生活费、一周目的地租金和基础设施摩擦）；入职失败会回滚区域和费用。
- NPC 跨区域就业成功后会立即同步住房租约到目的地，保留原有欠租和已缴押金，不再等待下一次日结才切换租住区域。
- 居民家庭现金、房租和消费预算统一使用默认货币的最小单位；商品初始价格按 USD 主货币计价，家庭采购时通过汇率转换，销售收入再换回企业 USD 主货币入账。
- 居民理论需求只在商品价格更新时进入供需模型一次；家庭已完成的线下购买不再重复写入交易成交量，避免必需品需求被双重计量。
- 家庭消费现在为企业仓库扣货建立一次性凭证；企业销售收入已入账但消费记录尚未写入时，重试仍会完成库存扣减，避免商品和资金不同步。
- 私人房东提取租金余额使用持久化提款记录和非收入邮箱转账；余额已扣但现金未到账时，房东登录会自动恢复。
- 工资日结的唯一权威改为劳动工资服务，家庭结算只读取已入账现金，避免工资在劳动阶段和家庭阶段重复发放。
- 玩家劳动者的工资在实体钱包到账之外，会以独立幂等来源进入其虚拟家庭预算；NPC 与玩家家庭都由同一个工资结算阶段提供家庭收入。
- 家庭消费记录已纳入经济审计：会校验家庭引用、商品数量、最小货币单位单价和总额乘法一致性。
- 劳动审计会校验有效雇佣的家庭、企业和唯一性，避免工资结算向失效或重复雇佣发放。
- 企业暂停、清算或解散后不能发布岗位或招聘；已有雇佣会结束，未付工资仍保留在工资账本中等待后续处理。

## 存在的问题

- 当前居民是经济模拟记录，不是 Minecraft 世界中的实体 NPC。
- 当前消费是虚拟消费者订单：会持久化商品、数量、单价和支出，并进入市场需求量；暂不向 NPC 实体发放物品。
- 岗位已有区域标识；坐标级通勤路线尚未实现，目前使用贸易区域距离代理。
- 当前迁移已计算目的地租金、通勤代理和基础设施摩擦，并会在搬迁成功时扣除一次性搬迁支出；真实坐标级路线仍未实现。
- 当前迁移摩擦以区域基础设施代理，尚未接入真实住房合同、通勤路线和搬迁服务商。
- NPC 迁移意愿已比较起点与目的地公共服务评分；在低满意度家庭中，医疗教育服务优势可以降低收入门槛，但最多抵消约 20%，不会替代工资、住房和通勤成本。
- 当前教育和健康仍是家庭平均指标，尚未拆分到家庭成员年龄、疾病和就学阶段；但教育已影响基础技能与求职保留工资，健康已影响劳动参与率和保留工资。
- 当前仍未记录每名成员的精确年龄、婚姻关系和亲属图谱；家庭合并命令是接入关系模型前的显式过渡层。

## 后续方向

1. 为岗位和家庭增加坐标级通勤时间、住房租约、押金和搬迁服务市场。
2. 将虚拟消费者订单与真实卖方库存、资金托管和交付进一步合并。
3. 增加失业持续时间、培训、精确成员年龄、婚姻关系和跨代人口流动。
4. 在经济数据稳定后，再把部分居民可视化为世界实体。
