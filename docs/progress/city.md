# 城市与公共服务系统开发进度

最后更新：2026-09-07

## 已实现功能

- 区域公共设施数量持久化，支持住房、学校和诊所三类设施。
- 管理员可使用 `/city facility add/remove <region> <type> <count>` 调整设施供给，并使用 `/city info [region]` 查看覆盖情况。
- 公共服务评分由住房、教育和医疗覆盖率综合计算，并进入家庭每日福利、企业厂址生产质量和 NPC 区域迁移决策。
- 政府公共预算每天支付设施维护费用；预算不足时设施逐步折旧，避免公共服务无限增长。
- 区域基础租金会随住房容量和人口压力变化；住房不足会提高租金和家庭支出。
- 住房租约、租金支付、欠租、押金和房东收支已有持久化记录，并纳入经济审计。
- 物流设施会影响运输时间、运输容量、运输风险和跨区域迁移摩擦。
- 管理员可使用 `/city project start <region> <type> <count> [contractor]` 创建公共建设项目；项目按日获得财政拨款后交付设施，资金不足时暂停，指定承包商时必须为可经营的建筑业企业并获得幂等合同收入。

## 存在的问题

- 公共设施目前仍是区域级抽象记录，没有绑定到具体建筑、施工项目、维修队伍和服务半径。
- 公共建设已支持建筑业企业承包、企业收入记录、材料扣除和基础竞标；指定承包商时必须有 `construction`、`builder` 或“建筑”专岗，缺料或缺少专岗劳动力则停工，但尚未形成专岗工时。
- 住房尚未形成完整的私人房东合同、驱逐保护和二级租赁市场；当前私人房东仍使用区域级授权模型。
- 教育和医疗已影响福利、技能和劳动参与，但尚未细分到成员年龄、疾病、就学阶段和真实服务排队时间。
- 迁移使用贸易区域距离作为通勤代理，尚未实现坐标级路线、住房搜索和迁移服务商。

## 后续方向

1. 将材料清单和抽象施工队列升级为连接材料采购、建筑劳动力、承包商和政府采购合同的建设市场。
2. 增加住房搜索、租金报价、通勤时间、拥挤度和区域房价的联动模型。
3. 让学校影响成员技能积累，让诊所影响健康恢复和劳动供给，并加入容量不足时的排队或服务质量下降。
4. 将公共服务、就业和住房共同纳入迁移选择，逐步替换当前区域级通勤代理。
5. 为城市指标增加历史统计，支持观察人口、财政、设施和产业之间的长期反馈。
