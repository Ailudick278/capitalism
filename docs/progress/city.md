# 城市与公共服务系统开发进度

最后更新：2026-09-07

## 已实现功能

- 区域公共设施数量持久化，支持住房、学校和诊所三类设施。
- 管理员可使用 `/city facility add/remove <region> <type> <count>` 调整设施供给，并使用 `/city info [region]` 查看覆盖情况。
- 公共服务评分由住房、教育和医疗覆盖率综合计算，并进入家庭每日福利、企业厂址生产质量和 NPC 区域迁移决策。
- 政府公共预算每天支付设施维护费用；预算不足时设施逐步折旧，避免公共服务无限增长。
- 区域基础租金会随住房容量和人口压力变化；住房不足会提高租金和家庭支出。
- 住房租约、租金支付、欠租、押金和房东收支已有持久化记录，并纳入经济审计。
- 物流设施会影响运输时间、运输容量、运输风险和跨区域迁移摩擦。
- 管理员可使用 `/city project start <region> <type> <count> [contractor]` 创建公共建设项目；项目按日获得财政拨款后交付设施，资金不足时暂停，指定承包商时必须为可经营的建筑业企业并获得幂等合同收入。
- 建设项目支持 `/city project bid <projectId> <companyId> <unitPriceMinor>` 提交报价；有效建筑业企业按最低合规单价中标并锁定合同价格。
- 中标或指定承包商后会创建 `PUBLIC_CONSTRUCTION` 通用合同，按单位更新履约数量，全部完成后结案，逾期由通用合同机制标记违约。
- 每个承包商建设单位会持久化记录建筑专岗工人日、平均技能和验收分数；分数低于 50 时标记 `REWORK_REQUIRED`，为后续返工和维护成本提供依据。
- 结算完成后按区域持久化记录每日人口、设施数量、公共服务评分、失业率、人均日租金、政府余额、维护支出和在建项目；管理员可用 `/city history <region> [days]` 查询历史指标。
- 历史指标新增财政压力分数，按国库覆盖维护和福利支出的天数计算；`/city history` 可用于识别公共服务削减风险。
- 维护失败和设施折旧会持久化记录，城市历史新增 `maintenanceCuts`，可区分正常维护支出与财政不足造成的服务削减。
- 财政压力达到 75% 时，政府自动暂停新增学校和诊所项目，仅保留住房压力响应；已有项目和关键设施维护不被取消。
- 政府会读取上一结算日的区域失业率；达到 30% 时按可配置比例向失业家庭发放区域稳定补贴，默认 10%，可用 `/government policy regionalSupport <percent>` 调整。
- 政府每日检查住房容量；人口超过住房容量可容纳人数时自动启动一个政府直营住房项目，已有项目在建时不重复立项，国库不足会使项目暂停。
- 政府也会按 70% 目标覆盖率检查学校和诊所，覆盖不足时分别启动一个政府直营项目；每类设施同一区域只保留一个在建项目。
- 设施维护具有明确财政优先级：住房优先，其次诊所，最后学校；住房和诊所可使用最低生活保障预算，学校维护会为家庭保障金保留余额。
- `REWORK_REQUIRED` 单位会在下一结算日由承包商承担原材料和原单位成本 25% 的返工费用；缺料或资金不足时保持待返工。
- 未完成返工的低质量单位会暂时从公共服务有效容量中扣除；返工完成后恢复容量，影响会传导到家庭福利、迁移和企业生产。

## 存在的问题

- 公共设施目前仍是区域级抽象记录，没有绑定到具体建筑、施工项目、维修队伍和服务半径。
- 公共建设已支持建筑业企业承包、企业收入记录、材料扣除、基础竞标、专岗工时验收、承包商返工追责和服务容量反馈；仍未形成完整工程质量责任合同。
- 住房尚未形成完整的私人房东合同、驱逐保护和二级租赁市场；当前私人房东仍使用区域级授权模型。
- 教育和医疗已影响福利、技能和劳动参与，但尚未细分到成员年龄、疾病、就学阶段和真实服务排队时间。
- 迁移使用贸易区域距离作为通勤代理，尚未实现坐标级路线、住房搜索和迁移服务商。

## 后续方向

1. 将材料清单和抽象施工队列升级为连接材料采购、建筑劳动力、承包商和政府采购合同的建设市场。
2. 增加住房搜索、租金报价、通勤时间、拥挤度和区域房价的联动模型。
3. 让学校影响成员技能积累，让诊所影响健康恢复和劳动供给，并加入容量不足时的排队或服务质量下降。
4. 将公共服务、就业和住房共同纳入迁移选择，逐步替换当前区域级通勤代理。
5. 将城市历史指标扩展到就业、租金、产业产出和金融风险，支持观察人口、财政、设施和产业之间的长期反馈。
