# 界面、网络与基础设施开发进度

最后更新：2026-09-05

## 已实现功能

- 使用 NeoForge 菜单、屏幕、按键映射和 payload 完成客户端/服务端交互。
- 已建立各主要系统的菜单、界面、命令和操作结果反馈。
- 世界地图已拆分为独立的 WorldMapMenu/WorldMapScreen，土地界面通过入口调用地图。
- 已建立土地、税务、市场、证券、银行等系统的数据同步 payload。
- 多数核心数据使用 SavedData 持久化，支持服务器重启后恢复。
- 已保留独立地图入口用于调试和问题定位，地图入口配置默认为关闭时可由配置控制。
- 构建流程已支持生成 JAR 后自动复制到本地 Minecraft 测试实例；`copyModJar` 已适配 Gradle 9 对外部目录的状态追踪限制。

## 当前边界与待处理问题

- 现有界面仍以功能验证为主，视觉层和交互一致性不是最终形态。
- 网络请求需要继续统一权限校验、参数校验、错误返回和重复请求处理。
- 大量数据同步时仍需要关注批量化、增量化和客户端缓存。

## 后续开发方向

1. 抽象统一的操作结果、错误码、权限检查和服务端事务模板。
2. 继续减少全量同步，完善增量同步、版本号和客户端缓存失效策略。
3. 后续引入 LDLib2 时只替换界面表现层，保持领域服务和网络协议稳定。
4. 建立跨系统的调试日志、数据迁移和存档兼容策略。

## 最近验证

- 2026-09-05：`build -x test` 已成功完成，源码编译、JAR 生成和测试实例复制均正常。
- Windows 中文路径下，Java `@argfile` 仍可能导致 Gradle worker 类路径失效；使用临时 ASCII 驱动器映射运行测试可以规避该 JDK/路径兼容问题。
- 2026-09-05：清理 Gradle 构建产物后，完整源码和测试代码编译成功；直接使用中文路径执行测试时仍会触发 `GradleWorkerMain` 类加载错误。Gradle 官方文档确认测试默认使用独立 JVM，当前已用 ASCII 驱动器映射验证通过。
- 2026-09-05：补充 JUnit Platform Launcher，并通过 ASCII 驱动器映射完成全部 8 项单元测试。
