## 阶段路线（当前状态）

1. 基础稳定：已完成文档编码修复、经济主体与来源 ID 统一、资金边界检查、跨系统结算保护和回归测试。
2. 居民经济闭环：已完成 NPC 家庭持久化、收入、消费、就业、年龄队列和带成本迁移的基础闭环。
3. 合同与市场联动：已完成合同索引、物流交付、仓储、付款、损失和违约的可重试基础流程。
4. 城市与区域经济：已完成区域需求、公共设施、住房租金、维护成本和公共服务结算的基础闭环。
5. 政府与宏观经济：已完成税务、财政、政策利率、债券偿付、银行流动性和金融风险传导的基础闭环。
6. 结算可靠性：进行中。每日结算已按三个持久化阶段协调；恢复时会跳过已完成阶段，并通过金融交易日志追踪跨对象副作用。商品成交、证券成交、供应订单、国债发行、拍卖挂单、货币兑换和玩家转账已有恢复路径；资金托管、实体物品兑换、批量分红和拍卖成交仍需继续收口到统一跨对象事务协调器。

## 开发与验收规则

- 每个跨系统操作必须有稳定主体 ID、来源或请求 ID、币种、金额、时间和状态。
- 重复调用不得重复扣款、发放、计税、交付或增加负债。
- 持久化顺序必须允许重启后继续完成，或进入明确的退款、损失、违约或坏账状态。
- `/economy-audit` 会报告金融交易日志和每日结算阶段日志中仍未完成的步骤，便于定位重启恢复或人工处理对象。
- `/economy-audit` 还会报告拍卖、商品、证券、供应订单、银行、汇兑和玩家转账等跨对象待处理记录，便于确认恢复任务是否仍有遗留。
- `/economy-audit` 还会检查通用合同的履约数量、完成前提和违约暴露金额，发现跨系统同步后的账本不变量异常。
- `/economy-audit` 还会检查政府财政流水和债券持仓的金额、余额、期限与利率边界。
- `/economy-audit` 还会检查家庭消费记录是否对应真实家庭，且数量、单价和总额一致。
- 新玩法必须同时提交实现、持久化、测试和对应系统日志；只写界面或只写内存状态不算完成。
- 经济参数应有现实含义和边界说明，但不直接复制现实国家的完整法律制度。
