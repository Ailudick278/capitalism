# 产业链深化第一批（2026-09-10）

## 已实现功能

本批调整 31 条默认配方，新增 `metallurgy/cathode_wire_drawing`。重点是让已有中间材料进入实际上下游生产，并收紧旧简化配方的绕行路径。数量、收入、能源和维护仍采用游戏批次单位，不表示真实工业物料衡算。

| 产业链 | 本批变化 |
|---|---|
| 铝 | 粗铝土矿 + 烧碱 + 水 → 氧化铝；氧化铝 + 石墨 → 铝锭。旧 `bauxite_refining` 不再直接产铝锭。精炼使用普通水，避免与需要氧化铝的净水剂形成启动循环。 |
| 铜、锡、镍 | 粗铜 → 铜精矿 → 阴极铜 → 铜箔 / 铜线；焊料改用锡和铜；镍锭与硫酸进入硫酸镍生产。保留通用铜锭拉丝路线。 |
| 晶圆与芯片 | 多晶硅 → 硅锭 → 硅晶圆 → 加工测试晶圆 → 晶粒 → 测试晶粒 → 封装芯片 → 终测芯片。晶圆加工消耗光刻胶、电子蚀刻液和电子溶剂，旧切割和封装配方不能跳过前段加工。 |
| PCB | 基板 + 铜箔 → 覆铜板 → 钻孔 → 蚀刻 → 阻焊；阻焊板、终测芯片、贴片元件、焊料 → 组装 PCB → 成品电路板。旧成品板配方 ID 保留，统一承接组装 PCB 的检测步骤。 |
| 电池 | NMC 前驱体接入硫酸镍、钴、锰和硫酸；LFP 接入磷酸；负极使用石墨；三条电芯装配路线均消耗铜箔。旧通用正极材料承接 LFP，不再用红石跳过正极化学品。 |
| 回收、电子化学品 | 黑粉处理消耗硫酸和工业水，回收锂盐与石墨，回收材料需重新加工，不能直接获得成品正极和负极。氢氟酸改用萤石与硫酸。 |

所有材料均复用已注册物品、模型和机器，不新增材质占位物品。

### 旧配置兼容

- 本批维护的配方记录 33 个历史签名，包括之前已经升级过的芯片封装和电路板配方。
- 加载已有 `industries.json` 时，在对应行业内核对 ID、输入、输出、收入、机器、工人、能源、维护、材料分类、质量、副产物、污染和危险标记。
- 只有完全匹配历史默认值的配方才替换为当前默认值。自定义数量或费用等字段不会被本批迁移覆盖，重复加载不会反复改写。
- 保留原配方 ID；新增配方和新增官方行业仍使用原有按 ID 合并机制。
- 迁移发生在加载后的内存配置，不强制覆盖玩家磁盘上的自定义 JSON。新增默认配置使用新配方。

### 验证

- `compileJava`、`compileTestJava` 通过。
- 独立 JUnit 启动器运行数据迁移与生产相关测试：18 项通过、0 项失败。新增测试覆盖历史 JSON 反序列化、重复迁移、行业隔离、缺少替代配方、独立可变映射、13 类自定义字段及曾经迁移过的电路板。
- `node tools/verify-industrial-chains.mjs` 通过：10 项关键材料依赖、249 种材料注册 / 模型 JSON / 中文名称。
- 脚本先更新 `industry-chain-audit.md`，再验证在移除关键中间材料时，下游不能通过其他默认配方或回收循环自启动。
- 审计得到 297 条显式配方、255 种产出，重复配方 ID 和未知机器类型均为 0。

## 存在的问题

- 配方可达性检查以原版输入、矿石掉落和没有默认生产者的外部投入作为来源；不证明矿物分布、机器建造、数量平衡、设备科技门槛和利润模型均可行。
- 整体静态审计仍有 1 条内部输入来源未解释、1 条自循环和 38 条图循环。回收循环不能单凭图结构判定为漏洞，仍需结合批次数量和成本评估。
- 现有英文资源缺少 155 个产业链材料名称，本批保留为本地化待办；中文名称检查通过。
- NMC 与 LFP 最终仍产出通用 `battery_cell`，未实现化学体系决定容量、寿命和用途。钴锰盐、铝集流体及电解液专用锂盐继续使用简化模型。
- Gradle 的 `test` 任务仍因已有 `GradleWorkerMain` 启动问题失败，不能宣称全量回归已通过。独立启动器和运行日志保存在 `tmp/`。
- 尚未进行游戏内验收。部分既有配方的机器类型改变，存量企业需要对应设备，实体机器需检查或重新选择配置；本批不迁移世界存档中的设备实体。

## 后续方向

1. 验证从矿物采集、设备建造到首块电路板和首组电池的游戏内启动路线，并按整条链核算批次产能与成本。
