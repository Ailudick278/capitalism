# 证券与期货系统开发进度

## 已实现功能

- 支持股票、债券、期货、持仓、报价、保证金和到期结算。
- 股票买单到期释放未成交余额时使用订单 ID 幂等退款凭证，服务器重启不会重复返还资金。
- 股票卖单到期返还股份同样记录持久化凭证，订单删除前后重试不会重复增加持仓。
- 主动撤销股票订单时，托管股份或资金也使用订单级幂等凭证，避免撤单重试重复返还。
- 股票撮合成交向卖方支付时使用买卖订单、成交数量和金额组成的交易凭证，重复结算不会重复支付成交款。
- 股票成交的印花税税源复用同一成交凭证，不会因重试生成随机的新税源。
- 买单部分成交后的剩余资金退款绑定买单 ID，订单写入和退款重试不会重复返还。
- 股票成交增加买方持仓时复用成交凭证，成交重试不会重复增加股份。
- 期货手动平仓将保证金入账和净持仓调整拆成可恢复的阶段凭证，重复平仓不会重复计入收益或成交量。
- 期货每日盯市的盈亏和到期保证金返还按持仓 ID、结算日和阶段保存凭证，日结重试不会重复记账。
- 期货强制平仓会同步回冲净未平仓量，并使用持仓级凭证避免重复调整市场成交量。
- 期货保证金提取使用玩家、提取前余额和金额组成的持久化凭证，保证金扣减后的钱包到账可安全重试。
- 股票分红先从企业资金池扣款，再按“企业、批次时间、每股金额、总额、股东”生成一次性到账凭证；在线和离线股东使用同一套邮箱结算，重启不会重复发放。
- 公开要约收购的股份转移在经济账本内使用要约级一次性凭证，卖方收款也通过同一要约的持久化到账凭证恢复。
- 支持企业 IPO、股权基础结构和持久化交易记录。

## 存在的问题

- 企业财务报表、股东治理、信息披露和市场深度仍不完整。
- 分红批次的资金扣款与股东到账目前仍是跨账本步骤，已具备可重试收款凭证，但还需要统一金融结算日志来覆盖极端崩溃窗口。
- 公开要约的买方钱包扣款仍依赖钱包附件，尚未与股份账本共享原子事务；异常中断时需要继续完善资金托管阶段。
- 期货价格与现货、库存、利率和风险预期的联动较弱。

## 后续方向

1. 接入统一企业资产负债表和现金流。
2. 增加股东投票、董事会、分红和并购。
3. 建立股票、债券、期货共用的金融结算日志，统一本金、收益、税费和风险准备金。
4. 增加市场操纵、信息延迟和风险传导的约束。
