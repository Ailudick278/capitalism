# 市场、供应链与物流系统开发进度

## 已实现功能

- 支持供应订单、现货交易、限价单、仓库、运输、燃料、保险和损失记录。
- 支持物流节点、货物交付、离线邮箱、费用结算和库存幂等入账。
- 货运合同已同步到通用合同索引；已接受的合同在货物交付时自动完成，运输损失时自动标记为违约。
- 交付事件会调用统一货运结算服务：资金充足时自动扣买方、记承运方收入并关闭应付账款；资金不足时保留可重试的应付状态。
- 家庭消费订单可以从企业仓库购买基础商品，扣减企业库存并将销售收入记入企业账本。
- 通用合同索引和货运领域桥接现在使用受约束的状态机，终结状态不能被领域同步重新打开。
- 供应订单创建、部分交付、完成、退款和损失事件现在同步到 `ContractType.SUPPLY`，通用合同可查询订单履约数量和最终状态。
- 预付款订单拥有独立托管流水；交付付款成功后才释放对应托管，取消或到期时只退还未释放余额。
- 运输损失会按丢失批次从未交付数量中扣除，并从订单托管中退回对应预付款；部分损失保留剩余订单，全部未交付批次损失才关闭供应合同并标记违约。补偿以运输批次 ID 幂等，避免重启或重复事件造成重复退款。
- 经济审计会校验每笔供应托管的余额守恒，确保未释放、已付款和已退款金额等于原始托管。

## 存在的问题

- 区域供需、库存成本、运输路线和价格形成仍不够动态。
- 多个持久化账本之间仍缺少统一事务协调器；当前通过来源 ID、交付记录、状态机和损失记录实现可重试，但极端崩溃窗口仍需要事务日志收口。

## 后续方向

1. 建立订单、库存、运输、交付和付款的统一状态机，并补充付款托管、退款和部分交付规则。
2. 增加区域价差、路线容量、延误、损耗和运力竞争。
3. 将人口消费从虚拟消费记录进一步扩展为实际居民供给、配送和短缺反馈。
