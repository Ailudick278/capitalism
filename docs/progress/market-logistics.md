# 市场、供应链与物流系统开发进度

## 已实现功能

- 现货买单先持久化买单意图并使用订单级付款引用，付款成功后先写入完整买单再开始撮合；登录恢复可补写付款后尚未落盘的买单，避免资金悬挂。
- 现货卖单先持久化卖单意图并托管商品，再写入完整卖单；登录恢复可补建商品已托管但订单尚未落盘的卖单，成交后按订单 ID 更新剩余数量。
- 现货卖单意图记录托管前仓储快照；恢复时仅接受未扣货或恰好扣除本单数量的状态，避免中断重放重复扣货。
- 货运保险保费使用货运编号稳定扣款来源，公司保费和个人保费退款也使用一次性凭证；投保重试不会重复收费或退款。

- 支持供应订单、现货交易、限价单、仓库、运输、燃料、保险和损失记录。
- 支持物流节点、货物交付、离线邮箱、费用结算和库存幂等入账。
- 货运合同已同步到通用合同索引；已接受的合同在货物交付时自动完成，运输损失时自动标记为违约。
- 交付事件会调用统一货运结算服务：资金充足时自动扣买方、记承运方收入并关闭应付账款；资金不足时保留可重试的应付状态。
- 家庭消费订单可以从企业仓库购买基础商品，扣减企业库存并将销售收入记入企业账本。
- 通用合同索引和货运领域桥接现在使用受约束的状态机，终结状态不能被领域同步重新打开。
- 供应订单创建、部分交付、完成、退款和损失事件现在同步到 `ContractType.SUPPLY`，通用合同可查询订单履约数量和最终状态。
- 预付款订单拥有独立托管流水；交付付款成功后才释放对应托管，取消或到期时只退还未释放余额。
- 运输损失会按丢失批次从未交付数量中扣除，并从订单托管中退回对应预付款；部分损失保留剩余订单，全部未交付批次损失才关闭供应合同并标记违约。补偿以运输批次 ID 幂等，避免重启或重复事件造成重复退款。
- 经济审计会校验每笔供应托管的余额守恒，确保未释放、已付款和已退款金额等于原始托管。
- 拍卖到期结算使用仓库幂等入账和卖家邮箱幂等凭证；结算标记在资产凭证完成后写入，重启可恢复且不会重复发货或重复付款。
- 现货商品订单到期和主动撤单会先完成订单级物资/资金返还凭证，再删除订单，服务器中断后可安全重试。
- 现货撮合现在先确认卖方收款凭证，再交割商品和减少订单数量；收款凭证失败时保留订单，避免出现“货物已交付但卖方未收款”。
- 商品价格更新已修正供需方向：成交需求和需求缺口抬价，生产/库存过剩压价；价格计算抽为纯函数并覆盖边界测试。
- 供应订单的个人预付款写入订单级支付引用，企业采购使用企业账本的一次性来源凭证；重试同一已完成支付不会再次扣款。
- 供应订单在付款成功后立即持久化完整订单快照；初次发货使用确定性批次键，与补货恢复逻辑统一，服务器在发货副作用中断后可从已存在的物流/库存记录继续推进。
- 供应订单付款前会持久化订单意图，付款后标记状态；玩家登录和日结会恢复未完成意图，使用原订单 ID 的个人支付引用或企业账本凭证补齐付款、托管和订单记录。
- 供应订单的买方付款、订单落盘和买方托管建立已接入统一金融阶段日志，恢复流程会补齐对应的完成状态。
- 每日结算会从持久化供应订单事件流重建通用合同状态；履约数量只补记领域事件与通用索引之间的差额，避免恢复同步重复累计。
- 补货履约按批次记录库存扣减、货物发运、供应商收款和托管释放；付款失败时保留未完成阶段，下一次补货可继续重试。
- 供应商邮箱到账凭证已作为收款完成条件；若到账后服务器尚未写入领域收据，重试会补写收据而不会重复计税或误判收款失败。
- 运输损失补偿按批次记录退款、托管冲回和进项税抵扣冲回阶段，重启后可定位并继续未完成的补偿步骤。
- 企业货物保险索赔的库存成本冲减使用索赔来源凭证，索赔到账后中断重试不会重复减少成本层。
- 物流保险索赔现在按统一阶段日志记录保险赔付、索赔落盘和货运合同关闭；赔付凭证未完成时不会提前关闭运输记录。
- 跨系统阶段日志采用单调状态：已完成阶段不会因重启重试重新变成未完成，避免审计和恢复列表反复出现同一笔资金动作。
- 物流损失记录现在保存供应商 UUID；若损失处理时供应订单补偿暂时失败，登录或日结会从持久化损失记录重新发起补偿。
- 无保险最终损失也会记录损失落盘和货运合同关闭/违约阶段，和保险索赔使用同一金融阶段日志。
- 待处理订单意图超时退款事件已映射到通用合同的已结束状态，订单查询与合同索引不会继续显示活动状态。
- 无保险损失的企业库存成本冲减也保存数量与成本结果凭证；重试会复用原始成本，不会二次扣减或夸大损失。
- 货运合同同步到通用合同索引时使用实际状态发生时间，不再把合同到期时间误写成未来的履约时间。

## 存在的问题

- 逐笔撮合现在保存成交双方、成交数量和成交前订单快照；卖方付款、买方交付、税务、成交量和订单更新均有统一成交意图与阶段日志，登录或日结可继续未完成成交。
- `/economy-audit` 会统一列出仍未清理的商品买卖意图、成交意图和供应订单意图。
- 供应订单托管审计会区分仍在履约的订单和已收货、丢失、取消或退款的终态订单，防止终态订单继续占用资金。
- 商品与股票市场审计会校验挂单的 UUID、标的、数量、价格、创建时间与编号，先拦住会破坏撮合簿的持久化脏数据。
- 物流审计会把在途、已交付、已丢失记录放在同一 shipment ID 集合中校验，保证交付和保险损失不会对同一票货重复结算。
- 市场邮箱现在提供只读账本快照供审计使用；货币、转账和物品队列都会校验接收玩家、币种/物品标识和正余额。
- 商品价格审计会校验当前价、基本面价、前收盘价均为正，并检查持久化 OHLC 历史的高低价关系和长度上限，避免异常价格污染 CPI 与居民消费。
- 市场审计同时检查持久化的净成交量与供需流量：允许买卖方向的正负值，但拒绝空商品键和可能导致价格计算溢出的极端累计值。
- 已完成成交历史会校验交易双方、数量、金额、手续费和市场标识，避免统计报表把自成交、负时间或超过成交额的手续费当成真实交易。
- 成交历史在写入和读取持久化数据时都会执行同一套校验，异常记录不会进入运行态；全局经济审计负责发现旧版本或外部篡改留下的问题。
- 成交数量大于零时总额必须为正；读取旧存档保留原始手续费值，负手续费会被拒绝而不是被静默归零。
- 商品限价单在 SavedData 写入层校验身份、商品、数量、价格和创建时间，重复订单不会写入；部分成交只能保持订单身份不变并减少正数数量。
- 活动买单会与钱包支付日志按订单引用、玩家和 USD 进行托管核对，支付金额必须覆盖剩余订单金额；缺失资金证据的买单会进入经济审计问题列表。
- 新建卖单通过 `commodity-sell-order:<订单>` 幂等引用扣除仓储库存，并在审计中核对托管商品与数量；重启恢复不会重复扣货。
- 卖单部分成交后，审计按“原始托管量覆盖剩余量”核对，避免把合法的部分成交误判为库存异常。
- 仓储幂等返还来源现在同时持久化物品 ID 与数量，取消单和过期单的返还记录可被审计，避免来源引用与实际货物不一致。
- 取消或过期卖单只有在返还已存在或本次返还成功后才删除订单；返还失败会保留订单等待重试。
- 买单部分成交产生的价差退款现在也必须先成功写入或确认已写入邮箱，失败时保留剩余订单状态，不再静默丢失退款。
- 商品成交结算按事务聚合检查卖方收款、货物交付、税费、成交量和订单更新五个完成阶段，阶段缺失会进入经济审计。
- 股票成交统一采用同类五阶段审计：股份交付、税费、卖方收款、成交量和订单更新必须全部完成，跨市场结算标准保持一致。
- 股票买单部分成交产生的价差退款也采用幂等邮箱写入保护，失败时不静默吞掉退款，与商品市场保持一致。
- 股票卖单扣股现在通过 `stock-sell-order:<订单>` 持久化扣股凭证，正常下单和重启恢复共用幂等路径，避免重复扣减持仓。
- 股票扣股凭证同时保存股票标识和原始扣股数量，审计会核对其是否覆盖活动卖单剩余量。
- 成交恢复审计按成交前数量判断订单是否已经完全消耗；部分成交必须仍能对应订单剩余量，并核对买方、卖方和标的。
- 供应订单的每个交付批次必须完成库存扣减、货物派送、供应商收款和托管释放；丢失批次必须同时完成货款退款与托管退款。
- 新供应托管记录保存整单数量，审计可把原始托管金额和订单数量、单价直接对账；缺少数量的旧记录仍可恢复但不做金额推导。
- 同一供应订单的托管重试必须复用相同金额和数量，防止恢复流程把不一致的第二笔托管误判为成功。
- 仓储消费来源现在持久化物品和数量元数据，重启后若重试参数不一致会拒绝，避免物品被重复或错误扣除。
- 批量仓储消费来源现在持久化按物品 ID 排序的材料签名，重试时材料清单必须完全一致。
- 供应订单事件流现在审计事件类型、订单参与方与物品身份、唯一事件键和交付量上限，再由事件流同步通用合同状态。
- 公司运输合同现在审计合同结构、同一 shipment 的开放合同唯一性，并将已结算/损失终态与交付/损失证据对账。
- 运输费用现在会对账合同报价、资本化应付金额和分阶段结算记录，结算阶段必须按扣款、收款、关闭应付的顺序推进。
- 跨市场恢复依赖的金融结算日志与每日阶段日志现在也有统一字段校验，异常状态会在经济审计中暴露。

- 区域供需、库存成本、运输路线和价格形成仍不够动态。
- 多个持久化账本之间仍缺少覆盖所有玩法的统一事务协调器；现货成交已先行使用成交意图和阶段日志收口，其他跨系统操作仍通过来源 ID、交付记录和状态机实现可重试。
- 供应订单的待处理意图已能恢复扣款后尚未落盘的订单；仍需下一阶段把恢复器扩展为统一的跨库存、物流、税务和退款状态机，并处理长期离线买方的超时策略。
- 待处理意图超过供应订单有效期后，会校验原支付凭证并将已付款意图退款；未付款意图直接清理，避免长期离线记录无限积累或资金永久悬挂。

## 后续方向

1. 建立订单、库存、运输、交付和付款的统一状态机，并补充付款托管、退款和部分交付规则。
2. 增加区域价差、路线容量、延误、损耗和运力竞争。
3. 将人口消费从虚拟消费记录进一步扩展为实际居民供给、配送和短缺反馈。
